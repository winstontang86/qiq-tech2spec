# SQL 自检规则内置副本（规格书生成使用）

> 本文件是 `qiq-tech2spec` 自带的 SQL/DB 规范规则副本，用于生成实现规格书时，对规格书中的 DDL / DML / 查询 SQL 进行自检查与先行修正。
>
> **使用本文件不要求运行环境安装 `qiq-audit-sql` skill**。如同时安装了 `qiq-audit-sql`，可以用该 skill 的最新实现做更完整审计；但本 skill 的规格书交付只依赖本文件即可完成基础自检。

## 适用范围

- 规格书 `§2.1` 中的新建库表、表结构调整 SQL。
- 规格书伪代码、接口契约中出现的 DML / 查询 SQL 片段。
- 与 DB 运行安全直接相关、需要在规格书中落地的配置、监控、部署约束。

若方案不涉及 SQL / DB，规格书 `§2.1.1 SQL 规范自检与修正记录` 必须写明“不涉及 SQL / DB”，不能留空。

## 等级定义

- **MUST（必须）**：不允许存在未解决违规。规格书交付前，MUST 未解决项必须为 0。
- **重要 RECOMMEND（重要推荐）**：原则上优先修正；确需保留时，必须在规格书 `§2.1.1` 写明未采纳原因、风险与接受人。

## MUST 规则

### 1. 命名与注释

- **MUST-1**：库名、表名、字段名禁止使用 MySQL 保留字。
- **MUST-2**：表名、字段名只能使用小写字母、数字、下划线；不能以数字开头；不能以下划线结尾；两个下划线之间不能仅是数字。
- **MUST-3**：所有表和所有字段都必须带 `COMMENT`。

### 2. DDL 底线

- **MUST-4**：`CREATE DATABASE` 必须显式指定 `CHARACTER SET`，且只能为 `utf8` 或 `utf8mb4`。
- **MUST-5**：`CREATE TABLE` 必须显式声明 `PRIMARY KEY`。
- **MUST-6**：主键列必须使用 `BIGINT UNSIGNED`；如因兼容存量不能满足，必须在 `§2.1.1` 明确登记为偏离并说明原因。
- **MUST-7**：索引涉及的列必须声明 `NOT NULL`。
- **MUST-8**：禁止使用 `FLOAT` / `DOUBLE`；小数使用 `DECIMAL`，金额优先使用整数最小单位。
- **MUST-9**：禁止使用 `ENUM`。
- **MUST-10**：禁止使用外键，包含 `FOREIGN KEY` 与 `REFERENCES`。
- **MUST-11**：索引设计禁止走极端：不能每列一个单列索引，也不能建立覆盖所有列的全列索引。

### 3. 破坏性库表操作

- **MUST-12**：禁止直接执行 `DROP DATABASE`。
- **MUST-13**：禁止直接执行 `DROP TABLE`。
- **MUST-14**：禁止 `ALTER TABLE ... DROP COLUMN`；表结构演进必须走 expand → migrate → contract。

### 4. DML / 查询

- **MUST-15**：`INSERT` 必须显式指定字段列表，禁止 `INSERT INTO tbl VALUES (...)` 省略字段名。
- **MUST-16**：`UPDATE` / `DELETE` 必须带 `WHERE` 条件。
- **MUST-17**：业务查询 `SELECT` 必须带筛选条件；全表扫描类任务必须在规格书中明确批处理范围、限速与监控。
- **MUST-18**：单条 SQL 中 `JOIN` 表数量不得超过 3；被关联字段类型必须一致，且关联字段应有索引。
- **MUST-19**：禁止 `CREATE PROCEDURE` / `CALL` 等存储过程用法。

### 5. DB 运行安全与生产底线

- **MUST-20**：所有 DB 必须有跨 AZ 主从节点；重要数据必须说明跨 Region 同步策略或明确不涉及。
- **MUST-21**：所有 DB 必须配置重要指标监控告警，至少覆盖连接数、连接使用率、死锁数、磁盘利用率、内存利用率。
- **MUST-22**：MySQL Client SDK 初始化必须显式配置连接超时时间。
- **MUST-23**：生产 DB 必须开启审计日志；不涉及生产 DB 时必须说明。
- **MUST-24**：新增 RO 组必须位于两个不同可用区。
- **MUST-25**：主实例必须开启延时 RO，防异常数据引发全局故障。

## 重要 RECOMMEND 规则

### 1. 引擎、字符集与字符序

- **REC-1**：建表使用 `ENGINE=InnoDB`；有事务时必须使用 InnoDB。
- **REC-2**：建表字符集推荐 `DEFAULT CHARSET=utf8mb4`，并与库字符集保持一致。
- **REC-3**：字符序避免使用 `*_bin`，优先使用 `utf8mb4_general_ci` / `utf8mb4_0900_ai_ci` 等非大小写敏感字符序。
- **REC-4**：表名保持小写，避免依赖 `lower_case_table_names` 的跨环境差异。

### 2. 字段、类型与默认值

- **REC-5**：除自增键和大字段外，字段尽量声明 `NOT NULL`。
- **REC-6**：`NOT NULL` 列提供合理 `DEFAULT`。
- **REC-7**：`DATETIME` / `TIMESTAMP` 列提供默认值。
- **REC-8**：表字段数控制在 99 以内。
- **REC-9**：表必备字段包含主键 `id`、创建时间、更新时间。
- **REC-10**：时间字段后缀遵循：时间戳 `_at`、日期 `_date`、月份 `_month`。
- **REC-11**：表达“是否”语义的字段命名为 `is_xxx`，类型使用 `TINYINT UNSIGNED`。
- **REC-12**：长度近似相等的字符串优先使用 `CHAR`。
- **REC-13**：大部分场景使用 `DATETIME`；跨时区场景补充时间戳或时区字段。
- **REC-14**：避免 `TEXT` / `BLOB`；必须使用时优先拆表并用主键关联。
- **REC-15**：业务上可用整数表达的小数优先使用整数，金额使用最小货币单位。

### 3. 索引与唯一性

- **REC-16**：索引命名遵循：主键 `pk_`、唯一索引 `uk_`、普通索引 `idx_`。
- **REC-17**：库名、表名、列名长度不超过 32 个字符。
- **REC-18**：业务唯一字段或唯一字段组合必须建立唯一索引。
- **REC-19**：`VARCHAR` 字段建索引时指定前缀长度，并保证区分度满足业务需要。
- **REC-20**：同一文件内对同一表的多条 `ALTER` 建议合并。

### 4. 查询性能与 SQL 写法

- **REC-21**：避免 `SELECT *`，显式列出所需字段。
- **REC-22**：`WHERE` 等号左右字段类型保持一致，避免隐式转换导致索引失效。
- **REC-23**：索引列不要套函数或表达式，例如 `DATE(col)`、`UPPER(col)`。
- **REC-24**：避免左模糊 / 全模糊查询，例如 `LIKE '%abc'`、`LIKE '%abc%'`。
- **REC-25**：`IN (...)` 元素数量控制在 200 以内。
- **REC-26**：使用 `ISNULL()` 判断 NULL，不使用 `= NULL` / `<> NULL`。
- **REC-27**：计数使用 `count(*)`，避免 `count(列名)` / `count(1)`。
- **REC-28**：超大分页使用延迟关联或子查询优化。
- **REC-29**：禁止 `ORDER BY RAND()`。

### 5. DB 选型、容量与安全

- **REC-30**：新建数据库优先 MySQL 8.0，不低于 5.7。
- **REC-31**：预计两三年超过 2000 万行的表，需要在规格书中给出分库分表策略。
- **REC-32**：启用严格 `sql_mode`。
- **REC-33**：慢查询监控与周期性 review 需要有落地方式。
- **REC-34**：数据库敏感字段必须加密存储。
- **REC-35**：对接 DB 的逻辑层必须使用参数化查询或转义机制，防止 SQL 注入。

## 规格书落地要求

`§2.1.1 SQL 规范自检与修正记录` 必须至少包含以下信息：

| 字段 | 要求 |
|---|---|
| SQL/表/章节 | 明确是哪张表、哪段 SQL 或哪个规格书章节。 |
| MUST 检查结果 | 逐项说明是否通过；未解决项必须为 0。 |
| 重要 RECOMMEND 检查结果 | 逐项说明已修正项与未采纳项。 |
| 修正动作 | 写明补充了哪些字段、索引、默认值、注释、配置或查询改写。 |
| 未采纳推荐项原因 | 无则写“无”；有则写业务原因、风险与接受人。 |

交付摘要必须展示：

- `§2.1.1 SQL 自检表` 是否已完成。
- MUST 未解决项数量。
- 重要 RECOMMEND 未采纳项数量。
- 未采纳原因是否齐全。
